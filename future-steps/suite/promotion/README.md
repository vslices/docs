# Promotion

## Propósito

VSlices necesita poder reconstruir cómo una idea pasó desde observación a definición sin fingir que siempre fue estable.

Trayectoria candidata:

```text
observation
-> candidate idea
-> repeated evidence
-> conceptual stabilization
-> ownership decision
-> promotion
-> canonical definition
```

## Preguntas mínimas

Antes de promover un concepto importante:

1. ¿Qué significa?
2. ¿Qué clase de conocimiento es?
3. ¿Quién tiene autoridad principal para definirlo?
4. ¿Quién lo utiliza?
5. ¿Dónde está definido hoy?
6. ¿Qué evidencia lo sostiene o tensiona?
7. ¿Cuál es su estado de madurez?
8. ¿Qué relaciones mantiene con otros conceptos?

## Tipos de conocimiento candidatos

- Foundations
- Mechanisms
- Product-owned concepts
- Principles
- Hypotheses
- Evidence

No deben convertirse en una taxonomía física rígida hasta demostrar utilidad.

## Regla de no duplicación

```text
definition
!= history
!= evidence
!= public projection
```

La definición canónica debe poder enlazar a evidencia e historia sin absorberlas.

## Publicación

Sólo después de organizar autoridad y definición debería diseñarse la proyección pública.

```text
canonical knowledge
-> deliberate public projection
-> documentation site
```

La navegación pública puede optimizar onboarding y aprendizaje sin convertirse en la fuente accidental de la ontología interna de VSlices.
