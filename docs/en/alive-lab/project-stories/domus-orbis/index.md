# Domus Orbis

*Documenting the home as a living system*

## What is Domus Orbis?

**Domus Orbis** is an experimental project focused on reducing friction in the everyday management of the home.

The project starts from a simple idea:

> The home is not just a place where tasks happen. It is a living system composed of decisions, purchases, payments, consumption, routines, forgotten tasks, priorities, and responsibilities that must be sustained over time.

Domus Orbis explores how software can help preserve domestic clarity without turning the home into an additional source of noise, anxiety, or technological dependency.

## Why it is in Alive Lab

Domus Orbis is part of **Alive Lab** because it works as a real laboratory for validating VSlices in an everyday domain, not only a technical one.

This project allows us to observe how VSlices Method, VSlices Docs Standard, VSlices Design, and eventually VSlices Framework can help move from a real need toward a small, documented, evolutionary, and validatable solution.

The goal is not to demonstrate an ideal architecture. The goal is to observe what documentation, decisions, artifacts, and boundaries appear when trying to solve a real problem with a low level of ceremony.

## Type of problem it represents

Domus Orbis represents problems where the difficulty is not necessarily technical complexity, but continuity.

Examples of tensions found in the project:

* purchases that must be made before money disperses
* lists that repeat, but are manually reconstructed
* simple tasks that fail because they depend on memory, energy, or focus
* domestic processes that seem small, but create stress when they are not sustained
* information that exists in external applications, but not as the household's own intention

These problems are useful for VSlices because they force us to carefully separate:

* real need
* current process
* small solution
* initial artifact
* future improvement
* premature automation

## What we want to validate

With Domus Orbis, we want to validate how to apply all the methodologies we have in VSlices Method.

In particular, we are interested in observing whether the approach we offer can:

* preserve intention before building a complete application
* reduce real friction without automating the whole process
* avoid overengineering
* produce useful documentation for resuming the work later
* generate small artifacts that can survive future iterations
* adapt to the evolution of the product itself without changing its essence

The main hypothesis is that methodologies should be able to adapt to circumstances and solve the problems that emerge from the everyday context of the home, without needing to solve everything through a complete system, while still allowing that system to eventually exist.

At the same time, this allows us to validate elements such as parallel cells within the same context:

* one that creates practical and useful solutions to specific pains through Slice-First
* one that solves tasks requiring more research through Problem-First, without compromising an efficient solution
* one that keeps discovering more elements and builds a strong foundation for a future SaaS through Context-First

## How to read this Project Story

This Project Story should not be read as a universal recipe.

Domus Orbis shows how a real project selected documents, artifacts, and steps according to its own scope. Another project could need less documentation, more documentation, or different documents.

The intention is to show a concrete application of VSlices Method in order to extract reusable learnings.

## Status

This Project Story is evolving.

The first documentation focuses on Iteration 0 of Domus Orbis. Future iterations may show how the initial artifact becomes stable behavior, tooling, validation, and possible integration with VSlices Framework.
