# Introduction

A continuity path is a way to navigate documentation from a concrete perspective.

It is not a mandatory sequence of documents.

It is a narrative reading that shows how knowledge connects, which documents explain each stop, and what documentary depth exists at each point.

For example, a team can navigate documentation from the perspective of a business scenario, a product, a work line, a capability, a decision, or a validation.

!!! principle "Continuity principle"

    A continuity path should help understand how a piece of knowledge connects with other documents, decisions, implementation, and learning.


## Continuity perspectives

Continuity paths can begin from different perspectives.

Each perspective answers a different question and allows documentation to be navigated from a different intention.

| Perspective                                              | Question it helps answer                                     | Main focus                                   |
| -------------------------------------------------------- | ------------------------------------------------------------ | -------------------------------------------- |
| [Business scenario](perspectives/business-scenario.md)   | Where am I working?                                          | Business processes                           |
| [Domain context](perspectives/domain-context.md)         | What language, rules, and boundaries belong to the business? | Domain modeling                              |
| [Software project](perspectives/software-project.md)     | What tools do I have to address the work?                    | Software scope                               |
| [Client product](perspectives/client-product.md)         | What can the user do in a system?                            | Experience, usage, and software coordination |
| [Consumable service](perspectives/consumable-service.md) | What capabilities does this system offer to others?          | Software capabilities                        |

One perspective does not replace the others.

It only defines where the reading begins.

## Documentary depth

A continuity path also helps show how deeply a point was documented.

A stop in the path can be barely identified, minimally explained, expanded, or maintained as a reference.

| Depth      | Meaning                                                                  |
| ---------- | ------------------------------------------------------------------------ |
| Identified | The knowledge exists, but still has little structure.                    |
| Minimal    | There is enough documentation to support nearby work.                    |
| Expanded   | There is more detail because there is complexity, risk, or coordination. |
| Reference  | The knowledge is stable and important for future work.                   |

This makes it possible to observe the documentation generated by VSlices without assuming that everything must have the same depth.

A path can show that one part of the system is well understood, another is under exploration, and another was only excluded from the current scope.
